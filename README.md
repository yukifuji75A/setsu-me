# SETSU：Me
---

## 1. サービス概要

本サービスでは、性格や価値観、モチベーションの源泉など自分の特徴を入力するだけで、自分自身の **取扱説明書(トリセツ)** を作成することができます。
作成した **トリセツ** はリンク一つで共有可能。友人、恋人、新環境での自己紹介や、チーム内のスムーズな相互理解など、オンオフを問わないあらゆるコミュニケーションをサポートします。

---

## 2. 制作背景・課題

### 2-1. 生まれた背景

近年、若者世代を中心にMBTIをはじめとした性格診断が広く流行しており、SNS上でも **「自己理解」** や **「自己の言語化」** への関心が急速に高まっています。

こうした中で、「単に診断して終わるのではなく、自分の特徴を客観的に可視化し、周囲に共有できるツールがあれば便利なのではないか」と考えました。

### 2-2. 課題の整理

**表に見えている困りごと：新しい環境で相手に本当の自分を伝えることができない、知ってもらうことができない**

本当に解決したい課題は以下の4点です。

* **自己紹介のネタ不足:** 新しい環境での自己紹介がいつも定型文になってしまい、自分の本当の持ち味やキャラクターを上手く伝えられない。
* **相互理解の時間ロス:** 新しい職場やコミュニティで、お互いの仕事の進め方の癖、得意・不得意、不調のサインを把握するまでに数ヶ月以上の時間がかかってしまう。
* **地雷や境界線の伝えづらさ:** 「これをされるとモチベーションが下がる」「こういう時にストレスを感じる」という繊細な部分を、相手に重く捉えられずに伝える手段がない。
* **言語化の壁:** 自分の活かし方やストレス要因を、自分一人では客観的に言語化できない。

#### 本当に解決したい課題：**自己の言語化が苦手な人でも、新しい環境で本当の自分を伝えれるようにしたい！**

## 3. 主な機能

### 3-1. 認証・ユーザー管理

* メール/パスワードによる登録・ログイン(Devise)
* LINEアカウント連携によるログイン・新規登録(OmniAuth + omniauth-line)
* アカウント設定画面からのメールアドレス・パスワード変更(LINEログインユーザーは変更不可)
* 利用規約・プライバシーポリシーページ

### 3-2. トリセツ作成

* 多ステップフォームでの基本情報・テーマ別追加情報の入力
* 入力データを元にAIが「取扱説明書風の解説文」と「自己分析レポート」を自動生成
* 回答の再編集(共有URLは維持したまま何度でも上書き可能)

### 3-3. マルチテーマ

* テーマ選択(デフォルト / 友だち)
* テーマごとに文体・構造を切り替え(単なる配色変更ではなく、見せる相手に合わせて構造自体を変える)
* 「恋人」テーマはモデル上に区分を用意済みだが、質問・生成ロジックは未実装(今後の改善で対応予定)

### 3-4. マイページ

* タブ切り替え(ページ遷移なしで「基本情報」「AI分析文章」を切り替え)
* 作成・保存済みトリセツのプレビュー表示

### 3-5. 外部共有

* テーマ別の共有用URL発行
* 共有URLを開くだけでログイン不要・第三者が閲覧できる専用ページ

## 5. AI機能・プロンプト設計

`ManualGeneratorService`(`app/services/manual_generator_service.rb`)がAI生成を担っています。

* OpenAI Chat Completions API(`gpt-4o-mini`)を`response_format: json_object`で呼び出し、`basic_spec`(人物紹介文)と`handling_guide`(自己分析レポート)をJSONで受け取って保存
* 共通の基本情報とテーマ別の回答をポジション(`position`)で組み合わせ、プロンプトに埋め込むユーザー情報を組み立てる(`introduction_lines` / `analysis_lines`)
* テーマ(`default` / `friend`)ごとにsystem_prompt・user_promptを出し分け、文体や生成する文章の種類を変える
  * `default`:客観的で第三者視点の「取扱説明書」風の文体、`basic_spec`と`handling_guide`の2種類を生成
  * `friend`:友だち本人が話しているような口語体、`basic_spec`のみを生成
* 単一の回答をそのまま並べるのではなく、複数回答の組み合わせ・整合性・矛盾から人物像を推論するようプロンプト内で指示し、推測を事実として断定しないよう制約を設けている

## 8. 技術選定理由

#### バックエンド：Ruby on Rails 8.0.0
* 認証・DB・API連携などWebアプリ開発に必要な機能が揃っている
* 開発速度が速く、全テーマ共通の基本情報とテーマ別の追加入力データを組み合わせる複雑なロジックを柔軟に実装できる
* 卒業制作での採用実績が多く、情報が豊富

#### フロントエンド：Tailwind CSS / Hotwire（Turbo + Stimulus）
* 独自パーツの多い「トリセツ」の画面を、素早く構築する
* マルチテーマ機能において、各テーマに応じたコンポーネントの構造的切り替えと、Tailwindの柔軟なスタイリングを組み合わせることで、破綻のないUI実装が可能になる
* Hotwire（Turbo + Stimulus）を使用し、多ステップフォームの入力データをステップ進行のたびにDBへ保存することで、ページリロードやブラウザバックによるデータ消失を防ぐ

#### データベース：PostgreSQL
* Railsとの相性が良く、主要PaaSで標準対応している
* 本番環境でも十分な性能を持ち、データの管理・運用が安全に行える

#### 認証：Devise + OmniAuth + omniauth-line
* Rails認証の定番であり、ログイン・会員登録機能を短期間で安全に実装可能
* LINEログインはOmniAuthと組み合わせることで、Deviseの認証基盤を維持したまま実装可能

#### AI分析：OpenAI API
* ユーザー情報から「取扱説明書」風のユニークな解説文を自動生成するために必須
* コストやテーマ別の文体出し分け（友だちなら口語体、デフォルトなら取扱説明書風の硬い文体など）の精度を検証して選定

#### デプロイ先：Neon
* PostgreSQLに特化したサーバーレスホスティングで、Railsの`DATABASE_URL`設定のみで接続でき、本番用DBとして導入コストが低い
* 無料枠があり、卒業制作の運用規模・予算に見合っている
